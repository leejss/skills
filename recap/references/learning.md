# Learning mode

Create a durable technical learning note for the user's future self. Extract transferable knowledge from the conversation instead of documenting the current project's implementation or task status.

## Keep technology, remove project identity

Remain specific about technologies when specificity is necessary for correctness. Keep names such as Next.js, NestJS, React, database engines, protocols, APIs, and version-dependent behavior.

Remove or generalize project-specific details:

- project, company, product, customer, and internal domain names
- repository paths and bespoke file layouts
- internal class, function, variable, endpoint, table, and event names
- proprietary business rules and identifying sample data
- incidental implementation status or task-management details

Turn a concrete project problem into a general technical problem. Replace copied project code with the smallest self-contained generic example that teaches the same idea. Do not claim the generic example is the project's exact implementation.

## Build understanding

Explain the topic at the level needed to understand and reuse it. Prefer:

- the motivating problem in generalized form
- core concepts and how they interact
- the mechanism or execution flow
- why a decision works, not only what was chosen
- alternatives, tradeoffs, and conditions that change the choice
- a small generic example when it materially improves understanding
- common failure modes and diagnostic clues
- when the technique applies and when it does not
- focused follow-up topics worth learning

Do not turn the note into a diary, task report, or chronological transcript.

## Ground additions

Use the conversation as the anchor, but add limited explanation needed to make the note coherent and educational. Clearly distinguish:

- conclusions established in the conversation
- general background explanation added for learning
- inference, uncertainty, or version-sensitive claims

Do not fabricate citations or pretend an added explanation was discussed. When an important claim cannot be supported confidently, qualify it or leave it as a question for further study.
